# Worcester County House Price Prediction

A machine learning project that predicts single-family home sale prices in Worcester County, MA (primarily Harvard, MA). Includes a full analysis notebook, a reusable data pipeline that fetches live data from Redfin, and an interactive Streamlit web app for price predictions.

## Project Structure

```
├── harvard_house_market_analysis.ipynb   # Analysis notebook: data → features → model comparison → export
├── data_pipeline.py                      # Redfin fetching, cleaning, caching + shared feature code
├── app.py                                # Streamlit prediction web app
├── model/
│   └── best_model.pkl                    # Trained model + metadata (generated by notebook)
├── data/
│   ├── harvard_sales_2026-03.csv         # Committed snapshot the notebook trains on
│   └── redfin_data.csv                   # Live-fetch cache (auto-generated, gitignored)
├── requirements.txt                      # Python dependencies
└── .gitignore
```

## Key Results

- **Dataset:** 47 single-family sales (45 in Harvard, MA), Mar 2025 – Feb 2026, from a frozen Redfin snapshot
- **Best Model:** Ridge regression, with a typical error of **$162k (17%)** under repeated 5-fold cross-validation. That's **36% lower** than always guessing the median price ($255k).
- **Top Price Driver:** square footage, by a wide margin. Bedrooms, lot size and bathrooms add a little. House age and sale month add essentially nothing.
- **Simple beats complex:** with 47 sales, Random Forest and XGBoost do no better than Ridge.
- **Interactive App:** users enter property features and get an instant price prediction.

## Notebook Sections

The notebook opens with a TL;DR, and each chart is followed by a one-line takeaway.

1. **Data** — load the snapshot and keep complete single-family sales (76 → 48 → 47)
2. **Features** — size measures, house age at sale, and sale month encoded as a cycle (7 features in total)
3. **What drives price?** — price distribution and each feature's correlation with price
4. **Model comparison** — median baseline vs Linear, Ridge, Random Forest and XGBoost, scored with repeated 5-fold CV
5. **Final model** — out-of-fold predicted vs actual, and permutation importance in dollars
6. **Export** — saves the model to `model/best_model.pkl` for the app
7. **Conclusions** — findings, limitations, next steps

## Data Pipeline

`data_pipeline.py` fetches sold-home data from Redfin's Stingray CSV endpoint:

- **Live fetch** with pagination and rate limiting
- **Local caching** (refreshes after 7 days)
- **Automatic fallback** to the committed snapshot if the network fetch fails
- **Cleaning**: snake_case columns, type coercion, deduplication, sparse column removal
- **Shared features**: `FEATURES` and `add_features()` are used by both the notebook and the app, so training and serving build features the same way

```python
from data_pipeline import load_data, load_snapshot
df = load_data()        # live Redfin fetch (or cache / snapshot fallback)
df = load_snapshot()    # the frozen snapshot the notebook trains on
```

## Streamlit App

An interactive web app where users input house features and get a predicted sale price.

**[Try the live app here](https://mahousepriceprediction.streamlit.app/)**

**Features:**
- Sidebar with sliders/selectors for square feet, beds, baths, lot size, year built, city, and sale month
- Large predicted price card with a ± typical error (the cross-validated MAE)
- Visual comparison to the price range in the dataset
- Refresh button that pulls the latest Redfin data into the local cache (retraining happens in the notebook)

### Run Locally

```bash
streamlit run app.py
```

## Limitations

- Small sample size (47 single-family sales)
- Geographic concentration — 45 of 47 sales are in Harvard, MA
- Short time span (~11 months) — insufficient for seasonal/macro trend modeling
- No interior quality features (finish, renovations, school ratings)

## Technologies

Python, pandas, scikit-learn, XGBoost, Matplotlib, Streamlit, Redfin Stingray API
